# Curated cross-game asset manifest -- the contents of redship-oot.o2r and
# redship-mm.o2r (#577 M1 split them, #577 M6 curates them).
#
# Format: <source>-><host> <archive-path-prefix>
#   source = the archive the resources are carved OUT of (oot | mm)
#   host   = the game that DRAWS them, which names the half they land in:
#              mm->oot  ->  redship-oot.o2r  (MM content OoT draws)
#              oot->mm  ->  redship-mm.o2r   (OoT content MM draws)
#   prefix = a path prefix in the source archive; end it with '/' to take a
#            whole object directory
#
# Each half carries its HOST's identity at runtime: rsbs/src/main.cpp mounts the
# host's half right after the host's base archives (and before its mods), and
# records redship-mm.o2r through MM's RecordMMArchivePath, so the per-archive
# factory dispatcher parses it as MM's.  Both halves must be non-empty.
#
# Paths are copied VERBATIM (see scripts/make_redship_otr.py for why), so every
# entry here must be absent from every base archive its host mounts (oot.o2r,
# soh.o2r and oot-mq.o2r for OoT; mm.o2r and 2ship.o2r for MM).  The generator hard-fails
# on a collision rather than shipping an order-dependent archive.  Colliding
# get-item objects are #577 M7's host-native mapping, not curated copies.
#
# It also hard-fails on Room/scene, Cutscene and Path resources.  Those three
# loader slots are resolved by OWNING ARCHIVE in single-exe builds
# (RsbsMMArchiveFactoryDispatcher, games/mm/2s2h/GameExports_SingleExe.cpp) and
# each half is registered as its HOST's archive while its content was exported
# by the other game, so anything of those types carried here would be parsed
# with the wrong game's reader.  Models are unaffected -- no model resource type
# is dispatched that way.
#
# Three further hard-fails guard the properties that make a model safe to draw
# under the OTHER game.  None is a style rule; each refuses the build and names
# the offending resource.
#
#   * Raw segmented texture references (#605).  A display list whose stream
#     carries a raw gsDPSetTextureImage resolves that texture against the HOST
#     game's segment table at draw time -- the OoTMM kObjectPatches[] hazard.
#     ~3.5% of each archive's object display lists carry one, so "cross-game
#     models work" is true PER MODEL, not universally.  Check before assuming
#     an object is curatable; the generator will tell you.
#
#   * Array resources the two games' readers parse differently (#604).  Vertex
#     arrays are safe (both factories run identical code).  Scalar arrays are
#     not: OoT's factory implements only S16/U16 and reads ZERO bytes for any
#     other width, desyncing the rest of the resource.
#
#   * References that escape their half (#577 M6).  Every texture, vertex
#     array, sub-display-list and matrix a curated display list names by path
#     hash must be curated in the same half.  OoT's get-item lists name shared
#     environment-map textures in gameplay_keep, so those textures are curated
#     below as single-path entries next to the models that need them.
#
# Every run prints an admission report: per half, the manifest entries and
# resources admitted, and how many of the HOST-EXCLUSIVE get-item directories
# (`objects/object_gi_*` the source carries and none of the host's base
# archives do) are covered.  The curated-archive-generator CTest row requires
# full coverage in both directions.  When a re-extraction or a port update
# changes that set, the row names the missing directory: curate it here, or
# record why it cannot be.
#
# Measured 2026-09-30 against archives extracted from the ROMs (oot.o2r, mm.o2r,
# soh.o2r, 2ship.o2r; no oot-mq.o2r): 36 of OoT's 77 `object_gi_*` directories
# and 43 of MM's 84 are host-exclusive.  Every one passes every guard once the
# five gameplay_keep textures below ride along.  The other 41 are shared by
# directory name and belong to #577 M7.
#
