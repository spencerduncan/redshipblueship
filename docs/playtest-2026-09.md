## 1. Get the build

**Take a release when one covers this build.** Each tag on the [releases page](https://github.com/spencerduncan/redshipblueship/releases) carries two assets: `redshipblueship-<tag>-windows.zip` and `redshipblueship-<tag>-linux.AppImage`. The first release of this build is `v0.2.0-prealpha` ("Trinity Alfa"): take `redshipblueship-v0.2.0-prealpha-windows.zip` or `redshipblueship-v0.2.0-prealpha-linux.AppImage` once that tag exists. Until then there is no release of it: the only one, `v0.1.1-prealpha` (July), is far older than this build, so use the CI build from `main` below. A CI build is also how to get something merged after the newest tag; such a build is **newer and untested**.

**Newer, untested: the CI build from `main`.**

- **Click path:** open the [latest `main` builds on nightly.link](https://nightly.link/spencerduncan/redshipblueship/workflows/generate-builds/main). Take `rsbs-windows.zip` (an unzipped Windows package inside) or `rsbs-linux.zip` (`rsbs.appimage` and `readme.txt`). nightly.link serves the newest **successful** `generate-builds` run on `main`, so it lags a fresh merge by the ~30 minutes a run takes.
- **Command line:** find the run, then download one artifact:
  ```
  gh run list -R spencerduncan/redshipblueship --workflow generate-builds.yml --branch main --status success --limit 3
  gh run download <run-id> -R spencerduncan/redshipblueship -n rsbs-windows   # or -n rsbs-linux
  ```
- **Newest builds at the time of writing (2026-10-16):** three code changes merged after `851b1ee9`, each with its own `generate-builds` run on `main`: PR [#945](https://github.com/spencerduncan/redshipblueship/pull/945) (the first launch also offers to extract Majora's Mask's ROM; run `38959064036` at `b787ba8e`, green), PR [#956](https://github.com/spencerduncan/redshipblueship/pull/956) (the Happy Mask Shop door opens at night in a paired world, A3; run `38968113510` at `9d53040e`, green) and PR [#957](https://github.com/spencerduncan/redshipblueship/pull/957) (a door or F10 into a game whose archive is missing is refused and the game plays on, instead of crashing; run `38973036000` at `8a77874a`, started 2026-10-16; nightly.link serves it once it is green). Between them, PR [#947](https://github.com/spencerduncan/redshipblueship/pull/947) changed only agent tooling (run `38963695552` at `755924b5`, green, plays like `b787ba8e`). The last build before them is run `38261362180` at `851b1ee9` (green, 2026-10-12); the run before that, `38250124816` at `dc141cce` (PR [#939](https://github.com/spencerduncan/redshipblueship/pull/939)), differs only by PR [#940](https://github.com/spencerduncan/redshipblueship/pull/940), which reformats source files and changes no behaviour. The version bump of PR [#946](https://github.com/spencerduncan/redshipblueship/pull/946) changes no behaviour either: from it on a build reads `v0.2.0-prealpha`.
- **Check that you have the right build.** The window title names the commit, for example `RedShipBlueShip v0.2.0-prealpha+<commit> (Trinity Alfa) (OpenGL)` on a build with the version bump and `RedShipBlueShip v0.1.1-prealpha+851b1ee (Morpheus Bravo) (OpenGL)` on one from before it (PR [#900](https://github.com/spencerduncan/redshipblueship/pull/900)); so does the About column of Settings > General (`Commit:`). It must be `dc141cc`, `851b1ee` or a later `main` commit; the night-door step of A3 needs `9d53040` or later.
- **Create your file after the last change to file creation or loading lands.** A paired file keeps what the build that created it wrote. If such a change merges after you download, take the new build and create a new file.
- **How long a download stays up:** CI artifacts expire 90 days after their run (run `38261362180`'s on 2027-01-10); release assets do not expire. You supply both ROMs; the first launch offers to extract both (Majora's Mask's since PR [#945](https://github.com/spencerduncan/redshipblueship/pull/945); on an older build, launch once with `--game mm` for it) ([`BUILDING.md`](BUILDING.md), [`mm-archive-setup.md`](mm-archive-setup.md)).

## 2. Fresh-file setup

1. **Back up, then start clean.** Copy your `Save/` and `Randomizer/` folders aside, then move the spoilers out of `Randomizer/` so it is empty. A creation never writes its spoiler over another paired world's spoiler of the same name, so one that an older build left in `Randomizer/` for the same seed and OoT settings leaves your new world without a spoiler ([#937](https://github.com/spencerduncan/redshipblueship/pull/937)). Everything below lives in the game's working folder (`SHIP_HOME` on Linux when it is set): `Save/`, `Randomizer/` (spoilers) and `logs/`.
2. **Every randomizer file is a paired file.** Every OoT randomizer generation in this build is a paired creation (`Combo_ForeignPairingRequested` is true for every authorable setting, and `playthrough.cpp` refuses to generate otherwise), so there is no single-game OoT rando file to use as a control ([#775](https://github.com/spencerduncan/redshipblueship/pull/775)). The only unpaired file is a vanilla one.
3. **Use a new paired file.** Do not use an old one:
   - Paired files created before PR [#895](https://github.com/spencerduncan/redshipblueship/pull/895) (2026-10-10) are not opened. Pressing A on one keeps you on the file list with the toast "Refused: Majora's Mask options differ": its MM half was made with the old MM start, which this build cannot restore ([#895](https://github.com/spencerduncan/redshipblueship/pull/895), traced in code). A file from before PR [#680](https://github.com/spencerduncan/redshipblueship/pull/680) (2026-09-17) that never entered Majora's Mask, or whose old crossing left a vanilla MM half, may show "Refused: This file has no Majora's Mask world" instead ([#836](https://github.com/spencerduncan/redshipblueship/issues/836)). There is no recovery path: erase it and create a new file.
   - A seed string does not make the same world it made on an older build: [#763](https://github.com/spencerduncan/redshipblueship/pull/763), [#774](https://github.com/spencerduncan/redshipblueship/pull/774), [#840](https://github.com/spencerduncan/redshipblueship/pull/840), [#874](https://github.com/spencerduncan/redshipblueship/pull/874) and [#895](https://github.com/spencerduncan/redshipblueship/pull/895) each moved generated worlds.
   - The file select does not load a paired world's spoiler on its own: a launch leaves it alone and shows no toast ([#939](https://github.com/spencerduncan/redshipblueship/pull/939)). A paired spoiler dropped onto the window is refused with the toast "Spoiler not loaded: it belongs to a paired world." (it would be an unfinishable solo OoT world). That refusal is expected.
4. **Set everything first.** Open the menu (Esc) and set Combo > Cross-Game Rules (including the Goal row under "Win Condition"), Combo > MM Randomizer, Combo > MM Tricks, and OoT's own Randomizer settings. All of it freezes when you press Generate in step 5.
5. **Generate the seed.** Randomizer > General. For a seed you choose, tick "Manual seed entry" and type it in the Seed box; leave the box empty for a random one. Press **Generate Randomizer** (enabled only on file select, with no file loaded). **No spoiler is written yet:** a paired world's OoT half is not finished at Generate, so its spoiler is written in step 6.
6. **Create the file.** On file select, pick an empty slot, choose the **Randomizer** quest, then **Start Randomizer** (grayed out until a seed exists, and again once a file has been created from that seed: the line under it then reads "This seed was used for file N. Please generate a new one first.", [#934](https://github.com/spencerduncan/redshipblueship/pull/934)), enter a name and confirm. The paired world is filled now, behind the creation overlay (A1), and the spoiler JSON is written to `Randomizer/<seed hash>.json` (the "Spoiler File:" line names it). Load the file and, still in Hyrule, open Combo > Windows > Toggle Combo Tracker: its Majora's Mask panel must show MM's world under its header (a "Checks: n / m" line and a "Checks" node), not an empty header ([#772](https://github.com/spencerduncan/redshipblueship/pull/772)). No file-select screen in this build shows an `[MM v]` / `[MM _]` marker, so do not look for one.
7. **Write down** the seed, the build commit, and every non-default setting. You need them for any report.

> **Between sessions, Combo > Cross-Game Rules, MM Randomizer and MM Tricks set up your NEXT file.** The pages lock at Generate and while a paired file is loaded, and are editable again on a fresh launch and after you return to the title screen. **Loading a paired file puts that file's own rules, options and tricks back into those pages** ([#781](https://github.com/spencerduncan/redshipblueship/issues/781)): whatever you changed is overwritten, and a toast names what was reset ("Restored from file: Goal", "Restored for Majora's Mask: Starting Hearts +1"). The file loads paired and its crossings agree with it. These toasts are findings to report with `stderr.txt`: any toast starting "Refused:" when you press A on a file (the file is refused and is not opened, [#836](https://github.com/spencerduncan/redshipblueship/issues/836): for example "File made by another build", "Cross-game record is damaged", "Cross-game record is missing" or "Majora's Mask options differ"; you stay on the file list, and Combo > Save Files shows the same words). None of them should happen with files made on this build.

## 3. Scenarios

**First session** (the riskiest step first, so a broken build costs one dungeon, not an evening):
1. Launch from a terminal in the game folder with stderr kept: `cmd /c "redship.exe 2> stderr.txt"` (Windows, from cmd or PowerShell; PowerShell's own `2>` writes UTF-16 and wraps each line as an error record) or `./rsbs.appimage 2> stderr.txt` (Linux). The pairing lines below go to stderr only; the `.log` in `logs/` does not contain them.
2. Create one file with the shipped defaults (§2) or the one non-default of step 3, timing it (A1).
3. Go to the Happy Mask Shop as child Link and cross (by day; at night too on a build with PR [#956](https://github.com/spencerduncan/redshipblueship/pull/956), A3). On the shipped defaults Closed Forest is On, so child Link cannot leave Kokiri Forest until the Deku Tree is beaten: the first crossing comes after the Deku Tree. For a quicker smoke file, set Randomizer > Logic/Access > Closed Forest = Off before Generate; that is a non-default and changes the world, so write it down. `stderr.txt` must now contain `[MM] pairing: arrival profile matches the creation-frozen identity` and `[MM] pairing: HYDRATED from the frozen MM half (saveType=rando`. A toast beginning "Refused:" (for example "Refused: Majora's Mask options changed") at the crossing, or no HYDRATED line, is the first finding: stop and report it.
4. Walk back through the Clock Tower door. Pick up one crossing in each direction (A4), choosing the hosts nearest the portals from A2's lists.
5. Then everything else, in order. **Save right before either final boss**, so a misfiring ending costs one fight: in OoT, any save just before the climb to Ganon; in MM, at the last owl statue before the Clock Tower rooftop. An owl save returns you to OoT, so cross back and climb the Clock Tower again.
6. Keep `stderr.txt`, `logs/` and the slot's `.redsave` for every report.

**Working as designed** (each of these reads like a bug):
- Every randomizer file is paired; there is no single-game OoT rando file (§2).
- The MM Randomizer and MM Tricks rows turn grey ("Already Decided") as soon as you press Generate, before any file exists (H3).
- MM Randomizer shows "Majora's Mask is suspended; these options stay editable." while OoT runs, even if Majora's Mask has never been started.
- No spoiler file appears at Generate; it appears when the file is created (§2).
- A Hyrule check hosting an MM item (a chest, or a shop shelf, Business Scrub or merchant, A4) gives nothing in Ocarina of Time (a chest's cutscene only shows the item; a shop still charges its price), and the spoiler's `locations` entry there names the "Blue Rupee" stand-in, which is never given (A4).
- Majora's Mask's start list is the Ocarina of Time and the Song of Time: the Kokiri Sword and the Hero's Shield are in MM's item pool, as in OoTMM ([#895](https://github.com/spencerduncan/redshipblueship/pull/895)). Your first arrival in Termina also pays out MM's two free starting checks, the Deku Mask and Song of Healing slots (`RC_STARTING_ITEM_DEKU_MASK` and `RC_STARTING_ITEM_SONG_OF_HEALING`), and each may hold any item, a sword or the Hero's Shield included. With "[Both Games] Shared Kokiri Sword" on ([#910](https://github.com/spencerduncan/redshipblueship/pull/910)), a Kokiri Sword you already hold in Ocarina of Time is on B in Majora's Mask when MM has no sword of its own.
- An owl save in Majora's Mask ends the MM session and puts you back in Ocarina of Time at the same place F10 does, not on a title screen. The Song of Time also saves the pair, and keeps you in MM.
- Loading a paired file overwrites any Cross-Game Rule, MM option or MM trick you changed at the title screen with the file's own, and a toast says which (§2).

Run them in order; later groups assume a created world. "Expect" is what the merged PRs state. Anything else is a finding.

### A. The single-bag fill ([#743](https://github.com/spencerduncan/redshipblueship/pull/743), [#744](https://github.com/spencerduncan/redshipblueship/pull/744), [#749](https://github.com/spencerduncan/redshipblueship/pull/749), [#758](https://github.com/spencerduncan/redshipblueship/pull/758), [#756](https://github.com/spencerduncan/redshipblueship/pull/756))

1. **Create a paired world with the shipped defaults; time it.** Expect a dimmed modal, "Creating Your Paired World", with a progress bar and "Placing item n of N in both worlds (round r, batch b)". On the development workstation, 30 real creations took 5.9-13.7 s (mean 7.2 s), all on the first attempt ([#743](https://github.com/spencerduncan/redshipblueship/pull/743)). Record your time and your CPU. A failed creation shows the toast "Not created: try a new seed or other options." and leaves no file. Report every failure with its seed.
2. **Read the crossings in the spoiler JSON,** under `combo.crossingStore`: `ootItemsInMM` lists OoT items on Termina checks, `mmItemsInOoT` MM items on Hyrule checks. Each row has `hostCheckName` and `itemName` (display names, such as "Lens of Truth"). On the ComboSingleBag pinned seed (`RSBSSINGLEBAG1`, shipped defaults) the store held 21 OoT items in MM checks and 53 MM items in OoT checks when [#766](https://github.com/spencerduncan/redshipblueship/pull/766) measured it, before [#840](https://github.com/spencerduncan/redshipblueship/pull/840), [#874](https://github.com/spencerduncan/redshipblueship/pull/874) and [#895](https://github.com/spencerduncan/redshipblueship/pull/895) moved the default worlds, so expect other counts there now; those are one seed's counts, and other seeds differ; each side hosts at most 64. At a Hyrule host, the OoT half's `locations` entry shows the stand-in "Blue Rupee"; the crossing row is what the chest must give.
3. **Walk into Majora's Mask and back.** As child Link by day, the Happy Mask Shop door lands you in South Clock Town at the Clock Tower exit, and the Clock Tower door lands you in the Market outside the shop. F10 in OoT must load straight into South Clock Town, and F10 in MM straight into the Market, never a title screen, with the items you left with ([#756](https://github.com/spencerduncan/redshipblueship/pull/756)). Expect no refusal on arrival and the same world each time. **At night too** (a build at or after `9d53040`, PR [#956](https://github.com/spencerduncan/redshipblueship/pull/956)): in the Market at night, walk into the Happy Mask Shop door: you cross, and the Clock Tower door brings you back outside it in the night Market. On a vanilla file the door still shows its "Apply during the day" sign and does not open, and in either file the Potion Shop, Bazaar and Shooting Gallery doors keep their "closed" signs at night. The crossing is child-only by design: as adult the Market is in ruins and has no Happy Mask Shop door.
4. **Pick up a crossed item in each direction.** Pick a host from A2's lists. In Hyrule an MM item can be in a treasure chest or the Treasure Chest Game's final prize (in every world, [#874](https://github.com/spencerduncan/redshipblueship/pull/874)), and with OoT's shuffles on, on a shop shelf ("Shop Shuffle", [#831](https://github.com/spencerduncan/redshipblueship/pull/831)), at a Business Scrub ("Scrubs Shuffle", [#854](https://github.com/spencerduncan/redshipblueship/pull/854)) or at a merchant ("Shuffle Merchants": the bean salesman, Medigoron, Granny's Shop or the carpet salesman, [#870](https://github.com/spencerduncan/redshipblueship/pull/870)). In Termina an OoT item can be in a chest, a shop slot (the Curiosity Shop's special and the Bomb Shop's fourth item in every world, the others with MM's "Shuffle Shops", [#840](https://github.com/spencerduncan/redshipblueship/pull/840)) or a Tingle map ("Shuffle Tingle Maps", [#860](https://github.com/spencerduncan/redshipblueship/pull/860)). A shop, scrub, merchant or Tingle names the other game's item in its offer and charges the slot's own price, and a shelf shows the item's model ([#858](https://github.com/spencerduncan/redshipblueship/pull/858)). What Ocarina of Time shows when you buy an MM item at a shelf, scrub or merchant has not been checked on this build: write down what you see. **An OoT item on a Termina chest** plays MM's get-item cutscene: Link holds up the OoT item's model ([#822](https://github.com/spencerduncan/redshipblueship/pull/822); MM's own model for an item both games have, such as the Hookshot, [#829](https://github.com/spencerduncan/redshipblueship/pull/829); a tinted note for an OoT song, [#853](https://github.com/spencerduncan/redshipblueship/pull/853); sparkles where MM cannot draw it) and a textbox reads "You found <item> (OoT)!" ([#884](https://github.com/spencerduncan/redshipblueship/pull/884), J). **An MM item on a Hyrule chest** plays OoT's get-item cutscene: Link holds up the MM item's model and a blue textbox reads "You found <item> (MM)!" with the MM item's name ([#845](https://github.com/spencerduncan/redshipblueship/pull/845), [#884](https://github.com/spencerduncan/redshipblueship/pull/884)). An item both games have (the Hookshot, for example) shows OoT's own model; an item with no drawable model (a boss remains, for example) shows the mystery-item stand-in. Nothing is given in Hyrule, and the chest's "Blue Rupee" stand-in is not given. Only with "Skip Get Item Animations" (Randomizer > General, under Enhancements) set to "All Items" is there no cutscene: then the only sign is a toast "You found <item> (MM)" in the corner ([#884](https://github.com/spencerduncan/redshipblueship/pull/884)). Either way the item reaches its home game at your next crossing into it, silently: the pickup was its one announcement, and a "You got <item>" toast on arrival is a finding ([#878](https://github.com/spencerduncan/redshipblueship/issues/878)). ### L. Combo Item Tracker: both games' items in one overlay ([#458](https://github.com/spencerduncan/redshipblueship/issues/458) U1-U3, [#873](https://github.com/spencerduncan/redshipblueship/issues/873))

The Combo Item Tracker is the one Item Tracker overlay for both games. Open it with Combo > Windows > Toggle Combo Item Tracker; like SoH's own Item Tracker overlay it has no close button, so the same row closes it. By default it floats over the game with no title bar and a clear background, and clicks pass through it. It has three sections, "Ocarina of Time", "Majora's Mask" and "Shared", each under its own header, with no note under it ([#927](https://github.com/spencerduncan/redshipblueship/issues/927)). **Live and snapshot:** the game you are playing reads its running save, so an item lights up the moment you get it. The other game shows its snapshot, the items it held when you left it (for Majora's Mask on a new paired file you have not yet taken into Termina, its file-creation state). In "Shared", rupees, the wallet, hearts, Double Defense, magic, arrows, bombs, bombchus, Deku Sticks, Deku Nuts, the hookshot and, in a triforce hunt, the Triforce Pieces count are one quantity for both games, and the pool is written at each switch and save, so this section does not follow your rupees between them; the HUD does (the Shared row's tooltip on Combo > Tracker Settings says so). A header with nothing under it means there is nothing to read yet, not an empty inventory. The overlay reads the game in memory, never a save file on disk.

1. **Icons.** Each game's section looks like that game's own Item Tracker: Ocarina of Time's like SoH's (an icon grid, faded while not held, a count under the icon), Majora's Mask's like MM's (one block per group, an item not held drawn faint, its count in the cell's corner). Shared draws the pool with the icons of the game you are playing. Majora's Mask's icons load when Majora's Mask first starts in a session: until then its section lists the items by name, dimmed while not held ([`known-issues.md`](known-issues.md)). With Window Type set to Window, or with Enable Dragging on (M), hovering an icon shows the item's name.
2. **One crossing each way.** On a new paired file, in Hyrule with the overlay open: Ocarina of Time is live, Majora's Mask shows its file-creation state (as names, see 1). Pick up an item in Hyrule: its icon lights up at once. Cross into Termina: Majora's Mask is live with its icons, Ocarina of Time shows exactly what you left with, and Shared switches to MM's icons with the values you crossed with. Get an item in Termina: it lights up at once, and the Ocarina of Time section does not change. Cross back: the reverse. Quit, reload and play: the same sections.
3. **Only while paused.** On Combo > Tracker Settings turn on Only Enable While Paused (M): the floating overlay shows only while the pause menu of the game you are playing is open, in both games.
4. An item in the wrong game's section, a gray note under a section's header, a snapshot that is not what you left with, a section with nothing under its header while its game's file is loaded or after you have played it this session ([#873](https://github.com/spencerduncan/redshipblueship/issues/873)), the wrong icon for an item, or a floating overlay that runs past the game window's edge (it shrinks to fit) is a finding.

### M. Combo > Tracker Settings and the native trackers ([#458](https://github.com/spencerduncan/redshipblueship/issues/458) U6, U7)

1. **Combo > Tracker Settings** holds the overlay's settings, as SoH's Randomizer > Item Tracker page holds its own: under "Item Tracker Settings", Background Color, Window Type (Floating or Window), Enable Dragging and Only Enable While Paused (shown only while Window Type is Floating), Icon Size (25-128 px, default 36) and Tracker Opacity; under "Item Tracker Sections", one checkbox each for Ocarina of Time, Majora's Mask and Shared. Each change shows on the overlay at once. Window gives the overlay a title bar and lets you move it.
2. **Check Tracker Settings** is SoH's own Check Tracker Settings, drawn in the page (its pop-out row's tooltip says the Combo Tracker takes its check colours). Change a status's colour: both of the Combo Tracker's Checks lists follow (I5). The other rows there change OoT's own Check Tracker only.
3. **The native trackers.** Combo > Windows holds three rows (H4). Majora's Mask's own Item and Check Trackers have no row any more: the Combo Item Tracker and the Combo Tracker replace them. Ocarina of Time's own trackers stay on SoH's Randomizer pages and draw only while Ocarina of Time is running ([#797](https://github.com/spencerduncan/redshipblueship/issues/797)).

## 4. What to report, and how

- **One issue per finding** at [`spencerduncan/redshipblueship`](https://github.com/spencerduncan/redshipblueship/issues), labelled `agent-tracking`. Title it with the symptom.
- **Body:** the build commit (Settings > General), the OS and GPU backend, the seed, every non-default setting (Cross-Game Rules including the Goal, MM options, tricks, OoT rando settings), exact steps from file creation, and expected vs. actual. Add the scenario number (for example "C3").
- **Attach:** the spoiler JSON, a screenshot, the newest `.log` file from `logs/` for crashes (its name carries the build, so each build writes its own) (a crash dump is written into that log), and `stderr.txt` for refusals (refusal reasons are printed to stderr, not to the `.log`). For a save problem, a copy of the `.redsave` and the slot's save files.
- Timings (A1) are useful even when they pass. Post them as one line each: seed, seconds, CPU.

## 5. Known gaps (from the "Unverified" / "Not verified" sections of the merged PRs [#723](https://github.com/spencerduncan/redshipblueship/pull/723)-[#795](https://github.com/spencerduncan/redshipblueship/pull/795))

- **Never played:** everything in PRs [#736](https://github.com/spencerduncan/redshipblueship/pull/736)-[#795](https://github.com/spencerduncan/redshipblueship/pull/795) was verified by tests and harness captures only. No goal ending, triforce piece, F10 handover, textbox icon, MM mod reorder or menu click has been seen in a running game.
- **Creation budget:** no creation needed more than two fill batches, which bounds a budget failure below about 10%, not at zero ([#743](https://github.com/spencerduncan/redshipblueship/pull/743)).
- **Hints:** no pair-level Way of the Hero. Foolish hints work in paired worlds since [#924](https://github.com/spencerduncan/redshipblueship/pull/924): OoT's Foolish hint draws again, and an MM free gossip stone sometimes calls an area "a foolish choice". OoT's gossip stones may hint an OoT check that holds a Majora's Mask item, by that item's name with " (MM)" ([#575](https://github.com/spencerduncan/redshipblueship/issues/575) H3b), and an OoT item that crossed is hinted by the Majora's Mask area that holds it ([#575](https://github.com/spencerduncan/redshipblueship/issues/575) H3a); a file created before that says "Termina" ([#743](https://github.com/spencerduncan/redshipblueship/pull/743)). Majora's Mask's own hints (Combo > MM Randomizer > Hints, off by default) name a check's area with OoTMM's preposition ("is hidden in the Southern Swamp"), never "Lone Peak Shrine & Grottos"; an MM item that crossed into Hyrule is named by its Hyrule area, and the stones hint it too ([#575](https://github.com/spencerduncan/redshipblueship/issues/575) H2, H3c).

- **Proof is conservative for shared quantities;** it could fail to prove on a profile nobody measured ([#744](https://github.com/spencerduncan/redshipblueship/pull/744)).

- **Capability-row crossings** (souls and similar, when armed) have no in-game pickup text check; an armed-souls MM half can hit the fill's 30 s abort ([#729](https://github.com/spencerduncan/redshipblueship/pull/729)).
