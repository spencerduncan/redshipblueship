## 2. Fresh-file setup

1. **Back up, then start clean.** Copy your `Save/` and `Randomizer/` folders aside, then move the spoilers out of `Randomizer/` so it is empty. A creation never writes its spoiler over another paired world's spoiler of the same name, so one that an older build left in `Randomizer/` for the same seed and OoT settings leaves your new world without a spoiler ([#937](https://github.com/spencerduncan/redshipblueship/pull/937)). On a build at or after `29e8dba` every spoiler an earlier build wrote counts as another world's, because the fingerprint changed ([#1004](https://github.com/spencerduncan/redshipblueship/pull/1004), [#1055](https://github.com/spencerduncan/redshipblueship/issues/1055)); only stderr says so (`[MM] spoiler: REFUSED ...`). Everything below lives in the game's working folder (`SHIP_HOME` on Linux when it is set): `Save/`, `Randomizer/` (spoilers) and `logs/`.
2. **Every randomizer file is a paired file.** Every OoT randomizer generation in this build is a paired creation (`Combo_ForeignPairingRequested` is true for every authorable setting, and `playthrough.cpp` refuses to generate otherwise), so there is no single-game OoT rando file to use as a control ([#775](https://github.com/spencerduncan/redshipblueship/pull/775)). The only unpaired file is a vanilla one.
3. **Use a new paired file.** Do not use an old one:
   - Paired files created before PR [#895](https://github.com/spencerduncan/redshipblueship/pull/895) (2026-10-10) are not opened. Pressing A on one keeps you on the file list with the toast "Refused: Majora's Mask options differ": its MM half was made with the old MM start, which this build cannot restore ([#895](https://github.com/spencerduncan/redshipblueship/pull/895), traced in code). A file from before PR [#680](https://github.com/spencerduncan/redshipblueship/pull/680) (2026-09-17) that never entered Majora's Mask, or whose old crossing left a vanilla MM half, may show "Refused: This file has no Majora's Mask world" instead ([#836](https://github.com/spencerduncan/redshipblueship/issues/836)). There is no recovery path: erase it and create a new file.
   - On a build at or after `fabe7d3` (PR [#1125](https://github.com/spencerduncan/redshipblueship/pull/1125), 2026-10-23), a paired file saved by any build before `fabe7d3` (`v0.3.0-prealpha` included, and the `main` builds after its tag) is not opened either: "Refused: This file has no Majora's Mask world" (Q1; [`known-issues.md`](known-issues.md), "The `v0.3.0-prealpha` save break"). The operator accepted this break; there is no migration. Finish an old file on the build that wrote it, or create a new one.
   - A seed string does not make the same world it made on an older build: [#763](https://github.com/spencerduncan/redshipblueship/pull/763), [#774](https://github.com/spencerduncan/redshipblueship/pull/774), [#840](https://github.com/spencerduncan/redshipblueship/pull/840), [#874](https://github.com/spencerduncan/redshipblueship/pull/874) and [#895](https://github.com/spencerduncan/redshipblueship/pull/895) each moved generated worlds.
   - The file select does not load a paired world's spoiler on its own: a launch leaves it alone and shows no toast ([#939](https://github.com/spencerduncan/redshipblueship/pull/939)). A paired spoiler dropped onto the window is refused with the toast "Spoiler not loaded: it belongs to a paired world." (it would be an unfinishable solo OoT world). That refusal is expected.
4. **Set everything first.** Open the menu (Esc) and set Randomizer > Cross-Game (including the Goal row under "Win Condition" and the rules under "Shared Items"), Randomizer > MM Randomizer, Randomizer > MM Locations, Randomizer > MM Tricks, and OoT's own Randomizer settings. All of it freezes when you press Generate in step 5.
5. **Generate the seed.** Randomizer > General. For a seed you choose, tick "Manual seed entry" and type it in the Seed box; leave the box empty for a random one. Press **Generate Randomizer** (enabled only on file select, with no file loaded). On a build at or after `bc93e65` (PR [#1116](https://github.com/spencerduncan/redshipblueship/pull/1116)), Generate fills the whole paired world behind the progress overlay (A1) and writes its spoiler and a seed package, `Randomizer/<icons>-<fingerprint>.rsbs-seed.zip` (Q2). On an older build **no spoiler is written yet:** a paired world's OoT half is not finished at Generate, so its spoiler is written in step 6.
6. **Create the file.** On file select, pick an empty slot, choose the **Randomizer** quest, then **Start Randomizer** (grayed out until a seed exists, and again once a file has been created from that seed: the line under it then reads "This seed was used for file N. Please generate a new one first.", [#934](https://github.com/spencerduncan/redshipblueship/pull/934)), enter a name and confirm. On a build before `bc93e65` the paired world is filled now, behind the creation overlay (A1), and the spoiler JSON is written to `Randomizer/<seed hash>.json` (the "Spoiler File:" line names it); from `bc93e65` on, creation is instant and uses the world Generate made (step 5). Load the file and, still in Hyrule, open Combo > Windows > Toggle Combo Tracker: its Majora's Mask panel must show MM's world under its header (a "Checks: n / m" line and its area list, always drawn: there is no "Checks" node to open since PR [#1137](https://github.com/spencerduncan/redshipblueship/pull/1137)), not an empty header ([#772](https://github.com/spencerduncan/redshipblueship/pull/772)). No file-select screen in this build shows an `[MM v]` / `[MM _]` marker, so do not look for one.
7. **Write down** the seed, the build commit, and every non-default setting. You need them for any report.

> **Between sessions, Randomizer > Cross-Game, MM Randomizer, MM Locations and MM Tricks set up your NEXT file.** The pages lock at Generate and while a paired file is loaded, and are editable again on a fresh launch and after you return to the title screen. **Loading a paired file puts that file's own rules, options and tricks back into those pages** ([#781](https://github.com/spencerduncan/redshipblueship/issues/781)): whatever you changed is overwritten, and a toast names what was reset ("Restored from file: Goal", "Restored for Majora's Mask: Starting Hearts +1"). The file loads paired and its crossings agree with it. These toasts are findings to report with `stderr.txt`: any toast starting "Refused:" when you press A on a file (the file is refused and is not opened, [#836](https://github.com/spencerduncan/redshipblueship/issues/836): for example "File made by another build", "Cross-game record is damaged", "Cross-game record is missing" or "Majora's Mask options differ"; you stay on the file list, and Combo > Save Files shows the same words). None of them should happen with files made on this build.

## 3. Scenarios

**First session** (the riskiest step first, so a broken build costs one dungeon, not an evening):
1. Launch from a terminal in the game folder with stderr kept: `cmd /c "redship.exe 2> stderr.txt"` (Windows, from cmd or PowerShell; PowerShell's own `2>` writes UTF-16 and wraps each line as an error record) or `./rsbs.appimage 2> stderr.txt` (Linux). The pairing lines below go to stderr only; the `.log` in `logs/` does not contain them.
2. Create one file with the shipped defaults (§2) or the one non-default of step 3, timing it (A1).
3. Go to the Happy Mask Shop as child Link and cross (by day; at night too on a build with PR [#956](https://github.com/spencerduncan/redshipblueship/pull/956), A3). On the shipped defaults Closed Forest is On, so child Link cannot leave Kokiri Forest until the Deku Tree is beaten: the first crossing comes after the Deku Tree. For a quicker smoke file, set Randomizer > Logic/Access > Closed Forest = Off before Generate; that is a non-default and changes the world, so write it down. `stderr.txt` must now contain `[MM] pairing: arrival profile matches the creation-frozen identity` and `[MM] pairing: HYDRATED from the frozen MM half (saveType=rando`. A toast beginning "Refused:" (for example "Refused: Majora's Mask options changed") at the crossing, or no HYDRATED line, is the first finding: stop and report it.
4. Walk back through the Clock Tower door. Pick up one crossing in each direction (A4), choosing the hosts nearest the portals from A2's lists.
5. Then everything else, in order. **Save right before either final boss**, so a misfiring ending costs one fight: in OoT, any save just before the climb to Ganon; in MM, at the last owl statue before the Clock Tower rooftop. An owl save returns you to OoT, so cross back and climb the Clock Tower again.
6. Keep `stderr.txt`, `logs/` and the slot's `.redsave` for every report.

**Working as designed** (each of these reads like a bug):

## 4. What to report, and how

- **One issue per finding** at [`spencerduncan/redshipblueship`](https://github.com/spencerduncan/redshipblueship/issues), labelled `agent-tracking`. Title it with the symptom.
- **Body:** the build commit (Settings > General), the OS and GPU backend, the seed, every non-default setting (Cross-Game Rules including the Goal, MM options, tricks, OoT rando settings), exact steps from file creation, and expected vs. actual. Add the scenario number (for example "C3").
- **Attach:** the spoiler JSON, a screenshot, the newest `.log` file from `logs/` for crashes (its name carries the build, so each build writes its own) (a crash dump is written into that log), and `stderr.txt` for refusals (refusal reasons are printed to stderr, not to the `.log`). For a save problem, a copy of the `.redsave` and the slot's save files.
- Timings (A1) are useful even when they pass. Post them as one line each: seed, seconds, CPU.
