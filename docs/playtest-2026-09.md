## 1. Get the build

No release has been cut since `v0.1.1-prealpha` (July), which is far older than this build. Use the CI build from `main`.

- **Click path:** open the [latest `main` builds on nightly.link](https://nightly.link/spencerduncan/redshipblueship/workflows/generate-builds/main). Take `rsbs-windows.zip` (an unzipped Windows package inside) or `rsbs-linux.zip` (`rsbs.appimage` and `readme.txt`). nightly.link serves the newest **successful** `generate-builds` run on `main`, so it lags a fresh merge by the ~30 minutes a run takes.
- **Command line:** find the run, then download one artifact:
  ```
  gh run list -R spencerduncan/redshipblueship --workflow generate-builds.yml --branch main --status success --limit 3
  gh run download <run-id> -R spencerduncan/redshipblueship -n rsbs-windows   # or -n rsbs-linux
  ```
- **Newest build at the time of writing (2026-09-30):** `generate-builds` run `36451032716` on `main` at `200adaea`, green. The PR merged after it ([#802](https://github.com/spencerduncan/redshipblueship/pull/802)) changes only documentation, which that workflow skips, so it produces no newer build.
- **Check that you have the right build.** Open the menu (Esc), then Settings > General; the About column shows `Commit:`. It must be `200adae` or a later `main` commit.
- **Create your file after the last change to file creation or loading lands.** A paired file keeps what the build that created it wrote. If such a change merges after you download, take the new build and create a new file.
- Artifacts are kept 90 days. You supply both ROMs; the first launch extracts them ([`BUILDING.md`](BUILDING.md), [`mm-archive-setup.md`](mm-archive-setup.md)).

## 2. Fresh-file setup

1. **Back up, then start clean.** Copy your `Save/` folder aside. Everything below lives in the game's working folder (`SHIP_HOME` on Linux when it is set): `Save/`, `Randomizer/` (spoilers) and `logs/`.
2. **Every randomizer file is a paired file.** Every OoT randomizer generation in this build is a paired creation (`Combo_ForeignPairingRequested` is true for every authorable setting, and `playthrough.cpp` refuses to generate otherwise), so there is no single-game OoT rando file to use as a control ([#775](https://github.com/spencerduncan/redshipblueship/pull/775)). The only unpaired file is a vanilla one.
3. **Use a new paired file.** Do not use an old one:
   - Paired files from before PR [#680](https://github.com/spencerduncan/redshipblueship/pull/680) (2026-09-17) load and play in Ocarina of Time (under the Cross-Game Rules they were created with). If such a file **never entered Majora's Mask**, it is not opened: the file select refuses it with "Not paired: This file has no Majora's Mask world" ([#836](https://github.com/spencerduncan/redshipblueship/issues/836)). If it **did** cross before #680, it either plays its old pre-#680 MM half or, when its MM options no longer match and its MM half cannot restore them, it is not opened ("Not paired: Majora's Mask options differ"). Either way there is no recovery path; create a new file.
   - Paired files from [#680](https://github.com/spencerduncan/redshipblueship/pull/680) up to the switch ([#743](https://github.com/spencerduncan/redshipblueship/pull/743)) load and play the old overlay world (crossed items still in their home pool). Nothing here applies to them.
   - Paired files from [#743](https://github.com/spencerduncan/redshipblueship/pull/743) up to [#772](https://github.com/spencerduncan/redshipblueship/pull/772) load and are safe to play, but the Combo Tracker's Majora's Mask panel shows "No data yet" for them instead of MM's world ([#772](https://github.com/spencerduncan/redshipblueship/pull/772)).
   - A seed string does not make the same world it made on an older build: [#763](https://github.com/spencerduncan/redshipblueship/pull/763) and [#774](https://github.com/spencerduncan/redshipblueship/pull/774) each moved generated worlds.
   - A paired world's OoT spoiler loaded on its own at file select is refused with a toast (it would be an unfinishable solo OoT world). That refusal is expected.
4. **Set everything first.** Open the menu (Esc) and set Combo > Cross-Game Rules (including the Goal row under "Win Condition"), Combo > MM Randomizer, Combo > MM Tricks, and OoT's own Randomizer settings. All of it freezes when you press Generate in step 5.
5. **Generate the seed.** Randomizer > General. For a seed you choose, tick "Manual seed entry" and type it in the Seed box; leave the box empty for a random one. Press **Generate Randomizer** (enabled only on file select, with no file loaded). **No spoiler is written yet:** a paired world's OoT half is not finished at Generate, so its spoiler is written in step 6.
6. **Create the file.** On file select, pick an empty slot, choose the **Randomizer** quest, then **Start Randomizer** (grayed out until a seed exists), enter a name and confirm. The paired world is filled now, behind the creation overlay (A1), and the spoiler JSON is written to `Randomizer/<seed hash>.json` (the "Spoiler File:" line names it). Load the file and, still in Hyrule, open Combo > Windows > Toggle Combo Tracker: its Majora's Mask panel must read "As of file creation.", not "No data yet" ([#772](https://github.com/spencerduncan/redshipblueship/pull/772)). No file-select screen in this build shows an `[MM v]` / `[MM _]` marker, so do not look for one.
7. **Write down** the seed, the build commit, and every non-default setting. You need them for any report.

> **Between sessions, Combo > Cross-Game Rules, MM Randomizer and MM Tricks set up your NEXT file.** The pages lock at Generate and while a paired file is loaded, and are editable again on a fresh launch and after you return to the title screen. **Loading a paired file puts that file's own rules, options and tricks back into those pages** ([#781](https://github.com/spencerduncan/redshipblueship/issues/781)): whatever you changed is overwritten, and a toast names what was reset ("Restored from file: Goal", "Restored for Majora's Mask: Starting Hearts +1"). The file loads paired and its crossings agree with it. These toasts are findings to report with `stderr.txt`: any toast starting "Not paired:" when you press A on a file (the file is refused and is not opened, [#836](https://github.com/spencerduncan/redshipblueship/issues/836): for example "File made by another build", "Cross-game record is damaged", "Cross-game record is missing" or "Majora's Mask options differ"; you stay on the file list, and Combo > Save Files shows the same words). None of them should happen with files made on this build.

## 3. Scenarios

**First session** (the riskiest step first, so a broken build costs one dungeon, not an evening):
1. Launch from a terminal in the game folder with stderr kept: `cmd /c "redship.exe 2> stderr.txt"` (Windows, from cmd or PowerShell; PowerShell's own `2>` writes UTF-16 and wraps each line as an error record) or `./rsbs.appimage 2> stderr.txt` (Linux). The pairing lines below go to stderr only; the `.log` in `logs/` does not contain them.
2. Create one file with the shipped defaults (§2) or the one non-default of step 3, timing it (A1).
3. Go to the Happy Mask Shop as child Link by day and cross. On the shipped defaults Closed Forest is On, so child Link cannot leave Kokiri Forest until the Deku Tree is beaten: the first crossing comes after the Deku Tree. For a quicker smoke file, set Randomizer > Logic/Access > Closed Forest = Off before Generate; that is a non-default and changes the world, so write it down. `stderr.txt` must now contain `[MM] pairing: arrival profile matches the creation-frozen identity` and `[MM] pairing: HYDRATED from the frozen MM half (saveType=rando`. A toast beginning "Not saved:" (for example "Not saved: Majora's Mask options changed.") or "Not paired:" at the crossing, or no HYDRATED line, is the first finding: stop and report it.
4. Walk back through the Clock Tower door. Pick up one crossing in each direction (A4), choosing the hosts nearest the portals from A2's lists.
5. Then everything else, in order. **Save right before either final boss**, so a misfiring ending costs one fight: in OoT, any save just before the climb to Ganon; in MM, at the last owl statue before the Clock Tower rooftop. An owl save returns you to OoT, so cross back and climb the Clock Tower again.
6. Keep `stderr.txt`, `logs/` and the slot's `.redsave` for every report.

**Working as designed** (each of these reads like a bug):
- Every randomizer file is paired; there is no single-game OoT rando file (§2).
- The MM Randomizer and MM Tricks rows turn grey ("Already Decided") as soon as you press Generate, before any file exists (H3).
- MM Randomizer shows "Majora's Mask is suspended; these options stay editable." while OoT runs, even if Majora's Mask has never been started.
- No spoiler file appears at Generate; it appears when the file is created (§2).
- A Hyrule chest hosting an MM item gives no item and no textbox, only a corner toast, and the spoiler's `locations` entry there names the "Blue Rupee" stand-in (A4).
- An owl save in Majora's Mask ends the MM session and puts you back in Ocarina of Time at the same place F10 does, not on a title screen. The Song of Time also saves the pair, and keeps you in MM.
- Loading a paired file overwrites any Cross-Game Rule, MM option or MM trick you changed at the title screen with the file's own, and a toast says which (§2).

Run them in order; later groups assume a created world. "Expect" is what the merged PRs state. Anything else is a finding.

### A. The single-bag fill ([#743](https://github.com/spencerduncan/redshipblueship/pull/743), [#744](https://github.com/spencerduncan/redshipblueship/pull/744), [#749](https://github.com/spencerduncan/redshipblueship/pull/749), [#758](https://github.com/spencerduncan/redshipblueship/pull/758), [#756](https://github.com/spencerduncan/redshipblueship/pull/756))

1. **Create a paired world with the shipped defaults; time it.** Expect a dimmed modal, "Creating Your Paired World", with a progress bar and "Placing item n of N in both worlds (round r, batch b)". On the development workstation, 30 real creations took 5.9-13.7 s (mean 7.2 s), all on the first attempt ([#743](https://github.com/spencerduncan/redshipblueship/pull/743)). Record your time and your CPU. A failed creation shows the toast "Not created: try a new seed or Majora's Mask options." and leaves no file. Report every failure with its seed.
2. **Read the crossings in the spoiler JSON,** under `combo.crossingStore`: `ootItemsInMM` lists OoT items on Termina checks, `mmItemsInOoT` MM items on Hyrule checks. Each row has `hostCheckName` and `itemName` (display names, such as "Lens of Truth"). On the ComboSingleBag pinned seed (`RSBSSINGLEBAG1`, shipped defaults) the store held 21 OoT items in MM checks and 53 MM items in OoT checks when [#766](https://github.com/spencerduncan/redshipblueship/pull/766) measured it; those are one seed's counts, and other seeds differ; each side hosts at most 64. At a Hyrule host, the OoT half's `locations` entry shows the stand-in "Blue Rupee"; the crossing row is what the chest must give.
3. **Walk into Majora's Mask and back.** As child Link by day, the Happy Mask Shop door lands you in South Clock Town at the Clock Tower exit, and the Clock Tower door lands you in the Market outside the shop. F10 in OoT must load straight into South Clock Town, and F10 in MM straight into the Market, never a title screen, with the items you left with ([#756](https://github.com/spencerduncan/redshipblueship/pull/756)). Expect no refusal on arrival and the same world each time.
4. **Pick up a crossed item in each direction.** Pick a chest from A2's lists; crossings are hosted only on chests. **An OoT item on a Termina chest** plays MM's get-item cutscene (sparkles, no model) and a textbox "You found <item>!" (J). **An MM item on a Hyrule chest looks different, by design:** Link holds nothing overhead and no textbox opens; the only sign is a toast "You found <item>" in the corner, and the chest's "Blue Rupee" stand-in is not given. Either way the item reaches its home game at your next crossing into it, announced by a second toast. A Hyrule crossing chest that gives a rupee or no toast, an item missing after that crossing, or a second copy after a save and reload is a finding. If `mmItemsInOoT` lists an MM Heart Container, Double Defense or Bombchus, pick that one up too: whether MM's give path delivers those three was never checked ([#738](https://github.com/spencerduncan/redshipblueship/pull/738)).
5. **Count the heart items in the spoiler JSON.** On the shipped defaults the two games' 76 Pieces of Heart, 15 Heart Containers and 2 Double Defense are trimmed to one set ([#744](https://github.com/spencerduncan/redshipblueship/pull/744)). Count the OoT half's `locations` ("Piece of Heart", "Piece of Heart (WINNER)", "Heart Container", "Double Defense"), `combo.mm.checks` (`RI_HEART_PIECE`, `RI_HEART_CONTAINER`, `RI_DOUBLE_DEFENSE`, and the OoT names with " (Ocarina of Time)") and `combo.crossingStore.mmItemsInOoT` ("Heart Piece", "Heart Container", "Double Defense"). Expect exactly **44 pieces, 6 containers and 1 Double Defense** (14 + 4 of OoT's, 30 + 2 of MM's, the Double Defense from either game). The container count follows the larger starting health: 5 at four hearts, 7 at two.
6. **Count hearts through a full clear,** if you get that far. The bar must stop at **20 hearts**, and no heart pickup should be dead ([#744](https://github.com/spencerduncan/redshipblueship/pull/744)'s walk: 50 heart pickups, 0 dead).
7. **One dead hookshot pickup is expected.** OoT's pool has 2 progressive hookshots and MM's has 1, and the games top out at different tiers, so exactly one of the three does nothing, in any order. A second dead one is a finding.
8. **Finish the pair.** Under the default goal (Ganon & Majora) a world the fill created should be finishable without reading the spoiler. In Termina the four boss remains stay in the boss rooms (the default profile does not shuffle them); beating the four temples should open the Moon and let you fight Majora ([#758](https://github.com/spencerduncan/redshipblueship/pull/758)).
9. **Exclusions reach the seed.** Generate a manual seed, note the five hash icons on file select, exclude one location (Randomizer > Locations > Excluded Locations) and generate the same seed again: the icons change. Clear the exclusion and generate again: the first icons come back ([#774](https://github.com/spencerduncan/redshipblueship/pull/774)).

### B. Tricks ([#696](https://github.com/spencerduncan/redshipblueship/pull/696), [#713](https://github.com/spencerduncan/redshipblueship/pull/713), [#729](https://github.com/spencerduncan/redshipblueship/pull/729), [#763](https://github.com/spencerduncan/redshipblueship/pull/763))

1. Open **Combo > MM Tricks**. Every trick is off by default. 37 of the 86 tricks are bound to logic; a trick the logic does not support yet, or one reserved for an Ocarina of Time item, stays in Disabled with its arrow greyed and says why on hover ([#763](https://github.com/spencerduncan/redshipblueship/pull/763), [#771](https://github.com/spencerduncan/redshipblueship/pull/771)).
2. **A keg-gated site: the Lone Peak Shrine boulder chest** (`RC_LONE_PEAK_SHRINE_BOULDER_CHEST` in `combo.mm.checks`). With "Use Powder Kegs as Explosives" **off**, logic opens that boulder only with Bombs, Bombchus or the Blast Mask, so that chest must never hold your first explosive (`RI_PROGRESSIVE_BOMB_BAG`, `RI_BOMBCHU*`, `RI_MASK_BLAST`) when no other one is reachable first. A trick-off world must never leave a Powder Keg as your only way through a boulder, hidden grotto or breakable wall; if it does, report the site.
3. **The world moves.** Create a second world from the same manual seed with the trick **on**. The placements should differ (the trick set is frozen into the identity), and a keg may now be required. Do the same with "Deku Stick Fighting".
4. **Two tightenings, every trick off** ([#763](https://github.com/spencerduncan/redshipblueship/pull/763)). In three seeds' spoilers: `RI_MASK_GIANT` is never on `RC_STONE_TOWER_TEMPLE_INVERTED_BOSS_HEART_CONTAINER`, `RC_STONE_TOWER_TEMPLE_INVERTED_BOSS_WARP` or `RC_GIANTS_CHAMBER_OATH_TO_ORDER` (logic kills Twinmold only with the Giant's Mask, magic and a sword); and if exactly two `RI_PROGRESSIVE_WALLET` exist across `combo.mm.checks` and `mmItemsInOoT`, neither is on `RC_CLOCK_TOWN_WEST_BANK_PIECE_OF_HEART` (it needs the Giant's Wallet). The Bow still kills Twinmold in game; logic no longer counts on it.
5. **The new trick rows** ([#763](https://github.com/spencerduncan/redshipblueship/pull/763)) are enabled, not greyed: "South Clock Town Chest with Nothing", "Guess Oceanside Spider House Code", "Backflip over Deku Palace Guards", "Climb Stone Tower with One Mask", "Complete Snowhead Temple using Hot Spring Water", "GBT Central Room without Zora using Fire & Ice Arrows or an OoT Magic Spell", "Great Bay Temple without Fire Arrows", "Walk Along Surfaces Out of Bounds", "Twinmold with Bow (MM)", "Twinmold with Fire and Ice Arrows (MM)", "Bank Rewards Require One Less Wallet". The tooltips of "Bomb Jump Fences as Goron", "Walk Along Surfaces Out of Bounds" and "Great Bay Temple without Fire Arrows" end with a parenthesised sentence beginning "In this randomizer". [#763](https://github.com/spencerduncan/redshipblueship/pull/763)'s Playtest section lists ten physical tries, one per new movement binding; report any that cannot be done with exactly the items it names. Its "Combo > Windows > Toggle MM Randomizer Options" path is retired: the tricks are on Combo > MM Tricks.

### C. Goals and endings ([#740](https://github.com/spencerduncan/redshipblueship/pull/740), [#742](https://github.com/spencerduncan/redshipblueship/pull/742), [#760](https://github.com/spencerduncan/redshipblueship/pull/760), [#769](https://github.com/spencerduncan/redshipblueship/pull/769), [#775](https://github.com/spencerduncan/redshipblueship/pull/775))

1. Before you press Generate Randomizer, Combo > Cross-Game Rules is editable: direction, Shared Ocarina, the Goal, and "Reset Combo Rules" (asks first). After Generate the rows are disabled and hovering one shows "This setting is disabled because:" with "Already Decided". Changing a rule must never change the loaded world.
2. **The Goal row** ("[Both Games] Goal", under "Win Condition"): Ganon & Majora (default), Any Final Boss, Triforce Hunt, Ganon, Majora. Hovering it, each of Any Final Boss, Ganon and Majora says which game may be unfinishable, and the tooltip says "The paired game ends when the goal is met. A final boss defeated before then sends you back into its game." Create under Ganon: when the progress window closes, a toast reads "Not proven: Majora's Mask may be unfinishable." ("Ocarina of Time" under Majora). The warning reads the proof, not the goal: under Ganon or Majora it appears only when the other half was not proven, so a missing toast there is not by itself a finding. A toast under Ganon & Majora is a finding. The same seed under another goal is a different world. After creation the row is greyed and shows the file's goal. At the title screen, change the row and load a file made under another goal: the file loads, a toast reads "Restored from file: Goal", and the row shows the file's goal again (§2's box). Cross into Majora's Mask: `stderr.txt` shows `arrival combo rules match` and no toast refuses the crossing. Then quit to the title screen and relaunch: the row still shows the file's goal (the restore was saved to `shipofharkinian.json`, key `gCombo.Rando.Goal`). Triforce Hunt is listed but refused at Generate ([#760](https://github.com/spencerduncan/redshipblueship/pull/760)).
3. **Ganon & Majora, Ganon first.** After Ganon's final blow and the white fade you land in Ganon's Tower as adult Link: no Chamber of the Sages, no credits, and OoT's stat timer keeps running. Cross to Termina, save in MM, quit, reload and defeat Majora: Majora's ending and credits play ([#769](https://github.com/spencerduncan/redshipblueship/pull/769)).
4. **Ganon & Majora, Majora first** (ideally as the Fierce Deity), on a new world. After the death cutscene you arrive in South Clock Town at the Dawn of the First Day as human Link with no mask, the cycle reset. Save, quit, reload, cross to Hyrule and defeat Ganon: OoT's ending plays ([#769](https://github.com/spencerduncan/redshipblueship/pull/769)).
5. **Single-boss goals.** Goal = Majora: Ganon sends you back to Ganon's Tower, Majora ends the game. Goal = Ganon: Majora sends you to a new cycle in South Clock Town, Ganon ends the game. ## 4. What to report, and how

- **One issue per finding** at [`spencerduncan/redshipblueship`](https://github.com/spencerduncan/redshipblueship/issues), labelled `agent-tracking`. Title it with the symptom.
- **Body:** the build commit (Settings > General), the OS and GPU backend, the seed, every non-default setting (Cross-Game Rules including the Goal, MM options, tricks, OoT rando settings), exact steps from file creation, and expected vs. actual. Add the scenario number (for example "C3").
- **Attach:** the spoiler JSON, a screenshot, the `.log` file from `logs/` for crashes (a crash dump is written into that log), and `stderr.txt` for refusals (refusal reasons are printed to stderr, not to the `.log`). For a save problem, a copy of the `.redsave` and the slot's save files.
- Timings (A1) are useful even when they pass. Post them as one line each: seed, seconds, CPU.

## 5. Known gaps (from the "Unverified" / "Not verified" sections of the merged PRs [#723](https://github.com/spencerduncan/redshipblueship/pull/723)-[#795](https://github.com/spencerduncan/redshipblueship/pull/795))

- **Never played:** everything in PRs [#736](https://github.com/spencerduncan/redshipblueship/pull/736)-[#795](https://github.com/spencerduncan/redshipblueship/pull/795) was verified by tests and harness captures only. No goal ending, triforce piece, F10 handover, textbox icon, MM mod reorder or menu click has been seen in a running game.
- **Creation budget:** no creation needed more than two fill batches, which bounds a budget failure below about 10%, not at zero ([#743](https://github.com/spencerduncan/redshipblueship/pull/743)).
- **Hints:** no pair-level Way of the Hero or barren analysis; crossing hosts are never hinted, and an OoT item that crossed is hinted as "Termina" ([#743](https://github.com/spencerduncan/redshipblueship/pull/743)).
- **Surplus filler can be dropped** when more MM items land in Hyrule than OoT items leave; only filler gives way ([#743](https://github.com/spencerduncan/redshipblueship/pull/743)).
- **Netplay and crossings share one 64-slot array;** a peer filling it can make a pickup refuse, loudly ([#743](https://github.com/spencerduncan/redshipblueship/pull/743)).
- **Proof is conservative for shared quantities;** it could fail to prove on a profile nobody measured ([#744](https://github.com/spencerduncan/redshipblueship/pull/744)).
- **MM's vanilla-shop bomb bag** is still a vanilla check; buying it after the shared bag is full is one dead purchase ([#744](https://github.com/spencerduncan/redshipblueship/pull/744)).
- **Capability-row crossings** (souls and similar, when armed) have no in-game pickup text check; an armed-souls MM half can hit the fill's 30 s abort ([#729](https://github.com/spencerduncan/redshipblueship/pull/729)).
- ~~**MM's own refusal toasts** are long and can run off-screen ([#749](https://github.com/spencerduncan/redshipblueship/pull/749)).~~ Closed by [#784](https://github.com/spencerduncan/redshipblueship/pull/784): each refusal is now one short line beginning "Not saved:", and the `PairingRefusalToastFit` row checks that every one fits the screen.
- **Profiles:** plentiful, scarce, minimal and trap profiles have not been played ([#739](https://github.com/spencerduncan/redshipblueship/pull/739)); the fill measurements come from one host with tricks off ([#758](https://github.com/spencerduncan/redshipblueship/pull/758)).
- **Clock shuffle:** its MM crawl is unmeasured and unpinned ([#729](https://github.com/spencerduncan/redshipblueship/pull/729)); after a withheld Majora, the new cycle always starts at 05:59 on day 0 ([#769](https://github.com/spencerduncan/redshipblueship/pull/769)).
- **Crossed MM hearts, Double Defense and Bombchus:** their in-game give was never checked (A4, [#738](https://github.com/spencerduncan/redshipblueship/pull/738)). **Hookshot:** one dead pickup by design (A7).
- **Loose mods:** no loose texture was checked on screen, and a `.meta` custom asset is uncovered ([#732](https://github.com/spencerduncan/redshipblueship/pull/732)). **MM Mods:** the arrows were never clicked live, and an unreadable folder mid-walk was simulated, not produced ([#764](https://github.com/spencerduncan/redshipblueship/pull/764)).
- **Small windows:** since [#795](https://github.com/spencerduncan/redshipblueship/pull/795) the `ui` tier's lint R9 measures every widget row of our Combo pages, Cross-Game Rules included, against its column at the run's profile; custom rows (the trick tables, the mod list and the Save Files table) are left out. [#795](https://github.com/spencerduncan/redshipblueship/pull/795) measured all three profiles, 832x600, 960x704 and 1280x800, and no row overran at any of them; CI checks 832x600 (row `UiSnapshotMin`) and the runner's desktop profile (row `UiSnapshot`, 1280x800 on the Linux runner), so 960x704 is not rechecked. R9 measures menu pages, not windows, so whether the tracker panes fit at 960x704 is not measured ([#759](https://github.com/spencerduncan/redshipblueship/pull/759)). No Combo page was rendered below 800 px wide, where the columns collapse to one ([#742](https://github.com/spencerduncan/redshipblueship/pull/742), [#771](https://github.com/spencerduncan/redshipblueship/pull/771); [#771](https://github.com/spencerduncan/redshipblueship/pull/771)'s narrowest render was 832x600). - **Crossing views:** no real game switch drives the tests; MM-hosted found state lags until the next save or switch, and OoT-hosted status in play is unchecked ([#766](https://github.com/spencerduncan/redshipblueship/pull/766)).
